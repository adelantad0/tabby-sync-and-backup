# 同步原理解析

多数传统同步工具在多台电脑并发编辑时极易发生配置文件覆盖损毁或服务器丢失。

**Tabby Sync & Backup** 从底层架构设计上杜绝此类问题，确立 **零数据丢失 (Zero Data Loss)** 保证。

---

## 核心设计：独立设备文件架构 (Device-Per-File)

插件不会让所有电脑盲目争抢写入同一个中心 `config.json` 文件，而是为每台设备分配独立的硬件身份指纹 (`deviceId`)。

```
您的存储路径（WebDAV 或云盘同步目录）
└── sync/
    ├── devices/
    │   ├── macbook-pro.json     # 设备 A 的加密状态文件
    │   ├── office-desktop.json  # 设备 B 的加密状态文件
    │   └── thinkpad-linux.json  # 设备 C 的加密状态文件
    └── meta/
        └── clock.json           # 兰伯特逻辑时钟状态
```

### 为什么该架构更具优势：
1. **彻底消除云端并发锁死**：无论是 iCloud、Dropbox 还是 WebDAV 在后台静默同步，各设备只写自己的文件，绝不发生锁文件与版本覆写冲突。
2. **完全离线可用**：出差离线数周无妨。接入网络后，插件会自动聚合其他设备的所有最新增量并安全合并。
3. **兰伯特逻辑时钟 (Lamport Clocks)**：使用严格的分布式因果关系定序，而非依赖经常走时不准的系统硬件物理时钟。

## 配置同步与备份的区别

| 特性 | 同步 (Sync) | 备份 (Backups / Snapshots) |
| :--- | :--- | :--- |
| **核心目标** | 确保所有设备拥有一致的最新配置 | 保存历史时间节点的完整镜像 |
| **删除行为** | 在一台设备删除配置，其它端随之删除 | 历史备份永远保留被删记录 |
| **触发时机** | 定时自动触发或手动点击 | 每次同步合并生效前强制生成，或随应用启动 |
| **典型场景** | 在公司电脑与家庭笔记本来回切换工作 | 误删服务器配置或改崩外观后一键回退 |

## 冲突处理：智能分叉无损保留

如果笔记本和台式机在离线期间同时修改了同一个 SSH 连接的主机名或端口，会怎样？

* **传统同步软件**：后上传的文件直接暴力覆盖前者，另一端的劳动成果付之一炬。
* **Tabby Sync & Backup**：校验 SHA-256 哈希识别分歧，采纳最新修改的同时，将另一版本自动分叉为安全的独立副本：
  ```text
  [生产服务器] (来自 MacBook 的最新修改)
  [生产服务器 (来自 Office-PC 的冲突副本)]
  ```
  两份配置完好如初，所有端口转发规则、环境变量与认证设置均无一遗失。

## 30 天墓碑机制 (Tombstone Cleanup)

当您主动删除某项配置时，系统会生成一条「删除墓碑记录」告知其他设备执行同步清理。墓碑记录会在 30 天后自动物理消除，保持存储空间整洁紧凑。
